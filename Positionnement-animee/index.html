Un autre div

Voici le point de départ : une page HTML simple, sans aucune règle de disposition. Le navigateur lit le code de haut en bas et pose les boîtes les unes après les autres : c’est le flux.

Un <div> est de type block : il prend toute la largeur disponible et passe à la ligne.

Un <span> est inline : il reste dans la ligne, à côté de ses voisins, comme un mot dans une phrase.

Le <div> suivant reprend donc une nouvelle ligne. Tout le reste du cours consiste à modifier ce comportement par défaut.

display: block : chaque élément occupe toute la largeur de son parent et va à la ligne, même si son contenu est minuscule.

Même réduit à 45 %, le bloc garde sa ligne entière : l’espace à droite reste vide. Deux blocs ne se mettent jamais côte à côte.

Avec block, width, height et margin sont tous respectés. C’est la valeur des structures : sections, articles, paragraphes.

Le texte coule comme de l’eau : un span reste dans la ligne, un deuxième continue, un troisième peut même se couper en deux, et la phrase continue sans jamais créer de nouvelle ligne.
width : 200 px et height : 60 px

✖ width et height sont ignorés ✔ horizontal : ça décale — vertical : ça déborde ✔ horizontal : ça décale — vertical : sans effet

inline vit dans le texte : il suit la ligne et peut se couper sur plusieurs lignes, comme un simple mot.

width et height sont ignorés (cadre rouge). La taille d’un inline dépend uniquement de son contenu.

Le padding horizontal décale le texte. Le padding vertical se peint par-dessus les lignes voisines : il n’agrandit pas la hauteur de la ligne.

Même chose pour margin : seules les marges horizontales produisent un décalage.

Le meilleur des deux mondes : les boîtes restent sur la même ligne (comme inline) mais acceptent width et height (comme block).

Piège classique : le retour à la ligne entre les balises dans le HTML crée un petit espace d’environ 4 px entre les boîtes.

L’astuce : font-size: 0 sur le parent (les enfants gardent leur propre taille) → les espaces disparaissent.

Par défaut, tous les éléments sont en position: static : ils s’empilent simplement dans le flux.

Avec static, top, right, bottom et left n’ont aucun effet : rien ne bouge d’un pixel (cadre rouge).

Frère après

position: relative seul ne déplace rien, mais l’élément garde sa place dans le flux (cadre pointillé).

top et left le décalent par rapport à sa position d’origine. Les frères ne bougent pas : la place reste réservée.

Effet très utile : un élément en relative devient un repère pour ses enfants en absolute (pastille orangée).

Quand le badge passe en absolute, ce texte remonte : le badge ne prend plus de place dans le flux.

Réflexe n° 1 : on commence par poser le repère sur le parent avec position: relative.

Le badge sort du flux : l’emplacement qu’il occupait disparaît (le texte remonte) et il se cale à 12 px du haut et de la droite de la carte.

Si le parent n’est pas positionné, le badge part se caler sur l’ancêtre positionné suivant… ou sur la fenêtre. D’où la règle d’or : parent relative + enfant absolute.

Sans positionnement, le bloc « Menu » vit dans le flux, au milieu du texte.

… et il finit par disparaître complètement de l’écran.

C’est exactement le problème que règle position: fixed.

Encore un peu de texte pour que le défilement continue et que le contraste entre les deux comportements soit bien visible à l’écran.

Avec position: fixed, le bloc reste collé au bord de la fenêtre du navigateur, quelle que soit la quantité de texte que l’on fait défiler.

C’est pour cela qu’on l’utilise pour les menus flottants, les boutons d’action rapide ou les bandeaux de cookies.

Le contenu continue encore un peu pour que la démonstration soit confortable à observer en classe.

Sans positionnement, le bloc fait partie du flux : il défile avec la page et finit par disparaître.

position: fixed : le repère est la fenêtre (le viewport). Le bloc reste collé en bas à droite, quoi qu’on fasse défiler. Idéal pour un menu, un bouton d’action, une barre de cookies.

Section C — et ainsi de suite

Un titre sticky ne dépasse jamais les limites de son parent.

Il exige un conteneur qui défile (overflow) et une hauteur.

Sans cela, sticky se comporte comme static.

Fin de la section C.

↕ défilement automatique — cliquez dans la liste pour mettre en pause ou reprendre

Un titre normal défile avec sa section et disparaît en haut. Notez les deux conditions de sticky : un conteneur qui défile (overflow) et une hauteur.

position: sticky + top: 0 : il suit le flux jusqu’au seuil, se colle, puis repart avec son parent quand la section est épuisée. Un mélange de relative et de fixed.

image

Le texte entoure l’image flottante : c’est le rôle de float.

Un flottant est retiré du flux.

Le cadre pointillé est le parent .article — regardez sa hauteur.

Sans float, l’image est un simple bloc : elle occupe sa ligne et le texte passe en dessous.

float: left : l’image se cale à gauche et le texte l’entoure. Mais regardez le parent : il ne compte plus la hauteur de l’image, qui dépasse sous le cadre !

L’annexe ne contient pas la propriété clear : on contient donc le flottant avec overflow: hidden sur le parent, qui reprend alors toute sa hauteur.

3 questions pour vérifier

1. Je veux des boîtes côte à côte avec une largeur et une hauteur :

Bravo ! inline-block reste dans la ligne tout en acceptant width et height. Raté : inline accepte la ligne mais pas les dimensions, block accepte les dimensions mais pas la ligne. C’est inline-block qu’il vous faut.

2. Un badge « NEW » dans le coin d’une carte :

Exactement : le parent en relative sert de repère, l’enfant en absolute se cale dessus. Pas tout à fait : sans repère sur le parent, le badge partirait se caler sur la fenêtre.

3. Un titre qui suit le défilement uniquement pendant sa section :

Oui : sticky colle l’élément le temps que son parent défile, puis le relâche. Non : fixed resterait collé à la fenêtre pour toujours, et absolute sortirait du flux.

Le tableau complet. Retenez surtout trois colonnes : dans le flux ?, dimensions et repère. C’est ce qui distingue toutes ces valeurs.

Et voici le squelette d’une vraie page, écrit uniquement avec l’annexe : relative + absolute pour les badges, sticky pour la navigation, float pour les colonnes. À vous de jouer !

BONUS HORS ANNEXE — display: flex, justify-content, align-items, gap, flex, flex-wrap et flex-direction ne figurent pas dans l’annexe CSS3 : ils sont dans le fichier bonus-flex.css.

Sans flex, les <div> s’empilent. Pour les mettre côte à côte, l’annexe propose inline-block ou float.

display: flex sur le conteneur : les enfants passent en ligne d’un seul coup. Bien plus souple que float.

justify-content répartit les items sur l’axe principal : space-between pousse les items aux extrémités.

align-items gère l’axe secondaire : ici center, les items se centrent dans la hauteur du conteneur.

gap espace proprement les items, et flex: 1 donne à un item toute la place restante (ici l’item 2).

flex-wrap: wrap : plutôt que de se compresser, les items passent à la ligne suivante — la base du responsive sans média query.

flex-direction: column : les axes sont inversés, l’axe principal devient vertical.
