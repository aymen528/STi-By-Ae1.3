1. Qu'est-ce qu'une base de données ?

Une base de données est un ensemble structuré et organisé de données, stockées de façon durable sur un support informatique, et destinées à être consultées, mises à jour et gérées par plusieurs utilisateurs ou applications.

Elle est gérée par un SGBD (Système de Gestion de Base de Données) — par exemple MySQL, PostgreSQL ou SQL Server — qui permet de créer, interroger, modifier et sécuriser les données tout en évitant les redondances et en garantissant leur cohérence.

Une base de données relationnelle organise les données en tables (lignes/colonnes) reliées entre elles par des clés (primaire, étrangère).

2. Qu'est-ce que le SQL ?

SQL (Structured Query Language) est le langage standard utilisé pour communiquer avec une base de données relationnelle : créer sa structure, y insérer et modifier des données, les interroger, et contrôler les droits d'accès.

3. Différence entre LDD, LMD et LCD

LDD

Langage de Définition des Données

Définit et modifie la structure de la base : tables, colonnes, contraintes.

CREATE, ALTER, DROP

LMD

Langage de Manipulation des Données

Permet d'interroger et de modifier le contenu des tables.

LCD

Langage de Contrôle des Données

4. CREATE TABLE en détail

Syntaxe générale :

CREATE TABLE nom_table (
    nom_colonne1  type1  [contrainte(s) de colonne],
    nom_colonne2  type2  [contrainte(s) de colonne],
    ...
    [CONSTRAINT nom_contrainte] contrainte de table (colonne1, ...)
);

Ordre à respecter pour chaque colonne : nom_du_champ → type → contrainte(s). Une colonne peut cumuler plusieurs contraintes, écrites à la suite (NOT NULL, CHECK, DEFAULT...).

4.1 Contrainte de colonne vs contrainte de table

TypeOù elle s'écritQuand l'utiliserExemple
Contrainte de colonne Juste après le nom et le type de la colonne concernée La contrainte ne porte que sur une seule colonne immat_Vehicule VARCHAR(10) PRIMARY KEY
Contrainte de table Après la liste de toutes les colonnes, précédée en général de CONSTRAINT nom La contrainte porte sur plusieurs colonnes à la fois (clé composée) CONSTRAINT PK_Location PRIMARY KEY (immat_Vehicule, NCIN_Cli)

4.2 PRIMARY KEY

Identifie une ligne de façon unique (valeur unique et non nulle obligatoire).

-- PK simple : contrainte de colonne
CREATE TABLE Client(
    NCIN_Cli VARCHAR(8) PRIMARY KEY,
    nom_Cli  VARCHAR(20) NOT NULL
);

-- PK composée (2 colonnes ou plus) : obligatoirement une contrainte de table
CREATE TABLE Location(
    immat_Vehicule VARCHAR(10),
    NCIN_Cli       VARCHAR(8),
    date_loc       TIMESTAMP,
    CONSTRAINT PK_Location PRIMARY KEY (immat_Vehicule, NCIN_Cli)
);

4.3 FOREIGN KEY / REFERENCES

Une clé étrangère relie une colonne (ou un groupe de colonnes) d'une table à la clé primaire (ou une clé unique) d'une autre table, afin de garantir l'intégrité référentielle.

-- En contrainte de colonne (raccourci REFERENCES)
CREATE TABLE Location(
    immat_Vehicule VARCHAR(10) REFERENCES Vehicule(immat_Vehicule),
    NCIN_Cli       VARCHAR(8)  REFERENCES Client(NCIN_Cli),
    ...
);

-- En contrainte de table (obligatoire si la clé étrangère porte sur plusieurs colonnes)
CREATE TABLE Location(
    immat_Vehicule VARCHAR(10),
    NCIN_Cli       VARCHAR(8),
    ...
    CONSTRAINT FK_Vehicule FOREIGN KEY (immat_Vehicule) REFERENCES Vehicule(immat_Vehicule),
    CONSTRAINT FK_Client   FOREIGN KEY (NCIN_Cli) REFERENCES Client(NCIN_Cli)
);

4.4 ON DELETE : avec ou sans CASCADE

Précise ce qui doit se passer dans la table fille quand la ligne référencée dans la table mère est supprimée.

OptionComportement à la suppression du parent
ON DELETE CASCADELes lignes filles correspondantes sont supprimées automatiquement.
(rien — comportement par défaut) / ON DELETE RESTRICT ou NO ACTIONLa suppression du parent est refusée tant qu'il existe des lignes filles liées.
ON DELETE SET NULLLa clé étrangère des lignes filles est mise à NULL (colonne doit accepter les NULL).
 
-- Avec CASCADE : supprimer un véhicule supprime automatiquement ses locations
immat_Vehicule VARCHAR(10) REFERENCES Vehicule(immat_Vehicule) ON DELETE CASCADE

-- Sans CASCADE : la suppression du véhicule est bloquée s'il a encore des locations
immat_Vehicule VARCHAR(10) REFERENCES Vehicule(immat_Vehicule)

4.5 CHECK : validation des valeurs

La contrainte CHECK(condition) refuse toute ligne qui ne respecte pas la condition indiquée. Elle s'écrit, comme les autres, après le nom du champ et son type — en contrainte de colonne, ou en contrainte de table pour nommer la contrainte ou la faire porter sur plusieurs colonnes.

FormeUsageExemple
CHECK(condition)Condition simple (comparaison, intervalle)duree_loc INT(3) CHECK(duree_loc > 0)
CHECK(col BETWEEN a AND b)Valeur comprise dans un intervalleAnnee_Acq INT CHECK(Annee_Acq BETWEEN 2000 AND 2022)
CHECK(col IN (...))La valeur doit appartenir à une liste autoriséemarque VARCHAR(20) CHECK(marque IN('Peugeot','Renault','Fiat'))
CHECK(col NOT IN (...))La valeur ne doit pas appartenir à une liste interditeVille VARCHAR(20) CHECK(Ville NOT IN('Inconnue','N/A'))
 
-- Contrainte de colonne : nom_champ, type, puis CHECK
CREATE TABLE Vehicule(
    immat_Vehicule VARCHAR(10) PRIMARY KEY,
    marque VARCHAR(20) NOT NULL
        CHECK(marque IN('Peugeot','Renault','Fiat','Opel','Volkswagen','Citroën')),
    statut VARCHAR(15) DEFAULT 'Disponible'
        CHECK(statut NOT IN('Hors service','Volé'))
);

-- Contrainte de table nommée, ajoutée après coup
ALTER TABLE Vehicule
ADD CONSTRAINT CK_Marque CHECK(marque IN('Peugeot','Renault','Fiat'));

4.7 Nomination des champs (bonnes pratiques)

  • Nom explicite et significatif (nom_Cli plutôt que n).
  • Pas d'espaces ni d'accents ; utiliser _ pour séparer les mots (date_acq, immat_Vehicule).
  • Éviter les mots réservés SQL (date, order, table…).
  • Rester cohérent dans toute la base : une clé étrangère reprend le nom de la clé primaire référencée (NCIN_Cli dans Client et dans Location).
  • Préfixer éventuellement par un suffixe/préfixe indiquant la table d'origine (_Cli, _Vehicule) pour lever toute ambiguïté dans les jointures.

5. ALTER TABLE en détail

ALTER TABLE modifie la structure d'une table déjà créée : ajouter, modifier ou supprimer une colonne ou une contrainte.

OpérationSyntaxeExemple
Ajouter une colonne ALTER TABLE t ADD COLUMN (col) type; ALTER TABLE Client ADD COLUMN (Tel_Cli) VARCHAR(10);
Les parenthèses sont facultatives pour une seule colonne.
Modifier une colonne ALTER TABLE t MODIFY COLUMN col nouveau_type; ALTER TABLE Client MODIFY COLUMN Tel_Cli INT(8);
Supprimer une colonne ALTER TABLE t DROP COLUMN col; ALTER TABLE Client DROP COLUMN Adresse_Cli;
Ajouter une contrainte CHECK ALTER TABLE t ADD CONSTRAINT CHECK (condition); ALTER TABLE Vehicule ADD CONSTRAINT CHECK Annee_Acq BETWEEN 2000 AND 2022;
Valeur par défaut ALTER TABLE t MODIFY COLUMN col type DEFAULT valeur; ALTER TABLE Client MODIFY COLUMN Ville VARCHAR(20) DEFAULT 'Tunis';
On modifie la colonne, on n'ajoute pas une "contrainte" séparée.
Remplacer la clé primaire (PK composée) ALTER TABLE t DROP PRIMARY KEY, ADD PRIMARY KEY (col1, col2, ...); ALTER TABLE Location DROP PRIMARY KEY ADD PRIMARY KEY (immat_Vehicule, NCIN_Cli, date_loc);
Supprimer la clé primaire ALTER TABLE t DROP PRIMARY KEY; ALTER TABLE Client DROP PRIMARY KEY;
Ajouter une clé étrangère ALTER TABLE t ADD CONSTRAINT nom FOREIGN KEY (col) REFERENCES autre_table(col) [ON DELETE CASCADE]; ALTER TABLE Location ADD CONSTRAINT FK_Client FOREIGN KEY (NCIN_Cli) REFERENCES Client(NCIN_Cli) ON DELETE CASCADE;
Désactiver / réactiver les contraintes ALTER TABLE t DISABLE KEYS; / ENABLE KEYS; ALTER TABLE Client DISABLE KEYS;
Renommer la table ALTER TABLE t RENAME TO nouveau_nom; ALTER TABLE Vehicule RENAME TO Voiture;

Règle pratique : ADD pour créer (colonne ou contrainte), MODIFY pour changer le type ou une valeur par défaut d'une colonne existante, DROP pour supprimer.

6. Exemple complet

Contexte : gestion de location de véhicules (Véhicule, Client, Location).

LDD Création de la structure

CREATE TABLE Vehicule(
    immat_Vehicule VARCHAR(10) PRIMARY KEY,
    marque VARCHAR(20) NOT NULL
        CHECK(marque IN('Peugeot','Renault','Fiat','Opel','Volkswagen','Citroën')),
    model VARCHAR(20) NOT NULL,
    date_acq YEAR NOT NULL
);

CREATE TABLE Client(
    NCIN_Cli VARCHAR(8) PRIMARY KEY,
    nom_Cli VARCHAR(20) NOT NULL,
    Ville VARCHAR(20) DEFAULT 'Tunis'
);

CREATE TABLE Location(
    immat_Vehicule VARCHAR(10) REFERENCES Vehicule(immat_Vehicule) ON DELETE CASCADE,
    NCIN_Cli VARCHAR(8) REFERENCES Client(NCIN_Cli) ON DELETE CASCADE,
    date_loc TIMESTAMP DEFAULT CURRENT_TIMESTAMP CHECK(date_loc <= NOW()),
    duree_loc INT(3) CHECK(duree_loc > 0),
    cout_loc DECIMAL(8,3) CHECK(cout_loc > 0),
    CONSTRAINT PK_Location PRIMARY KEY(immat_Vehicule, NCIN_Cli)
);

LDD Évolution du schéma

-- Ajouter un téléphone au client
ALTER TABLE Client ADD COLUMN Tel_Cli VARCHAR(10);

-- Corriger le type en numérique
ALTER TABLE Client MODIFY COLUMN Tel_Cli INT(8);

-- Renommer la table Vehicule
ALTER TABLE Vehicule RENAME TO Voiture;

LMD Manipulation des données

-- Ajouter une location
INSERT INTO Location(immat_Vehicule, NCIN_Cli, duree_loc, cout_loc)
VALUES ('123TU456', '01234567', 5, 250.000);

-- Nombre de locations par client, s'il en a au moins 2
SELECT NCIN_Cli, COUNT(*) AS "Nombre de locations"
FROM Location
GROUP BY NCIN_Cli
HAVING COUNT(*) >= 2;

-- Coût total encaissé par véhicule
SELECT immat_Vehicule, SUM(cout_loc) AS "Total encaissé"
FROM Location
GROUP BY immat_Vehicule
ORDER BY "Total encaissé" DESC;

-- Mise à jour : augmenter le coût de 10% pour les locations de plus de 7 jours
UPDATE Location
SET cout_loc = cout_loc * 1.10
WHERE duree_loc > 7;

LCD Contrôle des accès

-- Autoriser la lecture seule sur la table Client
GRANT SELECT ON Client TO 'secretaire'@'localhost';

-- Retirer le droit de suppression sur Location
REVOKE DELETE ON Location FROM 'secretaire'@'localhost';
